## 공개 요청과 내부 실행 참조

| 항목 | 계약 / 현재 수준 |
|---|---|
| 공개 분석 요청 | ticker는 ASCII 6자리, question은 비공백, as_of는 timezone 포함 시각, 멱등 키는 비공백. owner·AI payload·검증 통과·실행 ID를 공개 입력으로 지정할 수 없음 |
| 내부 문맥 | 검증된 Backend principal의 owner와 Backend 발급 request/run/attempt UUID를 연결. 타입·UUID·client_session_id·사용자 헤더는 인증이 아님 |
| 결과 참조 | AI report_id UUID와 해당 문맥·원본 JSON fingerprint를 연결. 같은 attempt의 다른 최종 결과는 충돌. fingerprint는 인증/수치 정답의 증거가 아님 |
| 실행/저장 상태 | 실행 pending/running/succeeded/failed/unknown과 저장 not_stored/stored/unknown을 분리. unknown은 자동 AI 재호출 근거가 아님 |
| 멱등·삭제 목표 | 같은 owner/키/입력은 같은 run, 다른 입력은 409. 삭제 후 늦은 저장으로 재노출 금지. **스키마 표현/순수 검증 수준이며 실제 접수·경쟁 제어·tombstone 서비스는 후속** |

원본 AI report_id를 Backend의 새 UUID로 조용히 교체하지 않는다. 같은 결과의 저장/게시 재시도에는
ID를 유지한다. run/attempt 정합성 채택 방식은 원본의 **제안**이며 실제 실행 연결을 구현했다고
표시하지 않는다. [실행 스키마](../../backend/src/api/schemas/flow_execution.py)가 현재 표현을 정의한다.

새 내부 자료 메타데이터 DataObservation은 source/as_of/period_start/period_end/unit을 요구하고
period_start≤period_end≤as_of, value가 null일 때에만 missing_reason이 있는 관계를 검사한다.
이를 과거 v1 wire 필드에 소급 추가하거나 모르는 출처/기간/결측 이유를 추정하지 않는다.

공통 신규 응답 목표는 request_id/data/error이며 data와 error 중 하나만 존재한다.
미인증 401·타인/없음 404·멱등/결과 충돌 409·공개 입력/미지원 version 422·내부 결과 계약 오류 502를
구분하고 안전한 code/message만 반환한다. 이 목표를 기존 모든 endpoint의 wrapper가 이미
동일하다는 뜻으로 사용하지 않는다. 자료 부족 결과와 내부 오류를 정상 분석 성공으로 게시하지 않는다.

## Flow payload version 1

[저장 입력](../../backend/src/api/schemas/flow_report.py)과
[중첩 검증](../../backend/src/api/schemas/flow_payload.py),
[순수 exporter](../../ai/src/agents/flow/export/to_json.py)가 상세 필드를 정의한다.

- version은 정수 1만 지원한다. report_id는 UUID, meta.ticker는 ASCII 6자리다.
  version/report_id/meta/signals/verification/interpretation의 필수 구조를 검사한다.
- meta.base_date는 실제 ISO 날짜 또는 명시적 null이다. 잘못된 날짜를 null로 바꾸지 않는다.
  stock_name/market은 문자열 또는 null, trace_id는 기존 추적 문자열/null 의미를 보존한다.
- 기존 signals 블록은 가산적 v1 호환으로 생략 가능하다. 존재하는 블록의 중첩 숫자·boolean·날짜와
  필수 관계는 검사한다. signals 전체 null은 자료 부족이다. **0은 수치이며 null/생략과 다르다.**
- NaN/무한대·숫자 자리에 boolean·숫자 문자열을 허용하거나 숫자로 보정하지 않는다.
  payload의 추가 JSON 키는 보존하되 공개 요청의 알 수 없는 입력 필드는 거부한다.
- 중첩 키/문자열 값과 저장 문자열의 NUL·단독 surrogate 등 PostgreSQL JSONB/UTF-8에 표현할 수
  없는 값은 **쓰기 전에 거부**한다. 삭제·치환·정규화로 원본을 고치지 않는다.
- data_status/outcome/regen_count/interpretation_meta의 과거 생략/null 호환을 유지한다.
  제공된 값은 gate·interpretation·출처 정합성을 검사한다. 상세 validator의 관계를 임의 강화하지 않는다.
- producer 의미: 순매수 daily/inst_detail/persistence는 백만원, strength.ratio는 비율,
  consecutive.days는 일수, ownership.ratio와 change_rate는 %, close/change는 원,
  volume/frgn_qty/inst_qty는 주다. persistence는 최근 5/20 거래일이며 daily/ownership/price_daily는
  각각 최대 20/5/10 거래일이다. 실제 날짜를 보존하고 달력일·원천 기준시각을 추정하지 않는다.
  문서 주석의 단위 충돌과 이미 생성된 0의 결측 여부를 저장 단계에서 임의 보정하지 않는다.

검증 실패는 종목 생성/결과 저장보다 먼저 발생해야 한다. 중첩 타입 오류를 처리되지 않은
AttributeError로 누출하지 않고, 저장과 조회에서 ID·수치·기간·version·검증 정보를 유지한다.

## 한시 JSONB 보존과 legacy

검증된 최종 payload 전체를 기존 flow_report_verifications.checks의 Backend 예약 영역에
한시 보존한다. gate1/2/3 매핑은 유지하며 **전용 snapshot 저장소의 최종 구조가 아니다**.
저장 형식 표식과 payload version을 구분한다. 추가 필드·생략·명시적 null·JSON 타입을 유지하며
원문 바이트 동일성은 보장하지 않는다. JSON 숫자 0과 boolean false는 같은 값으로 비교하지 않는다.

snapshot/신규 표식이 있는 기록은 신규 reader만 사용한다. root·해석·검증·공통 index와 snapshot을
대조하고 누락·손상·미지원 version이면 안전한 오류로 닫는다. legacy 재구성으로 우회하지 않는다.
둘 다 사라져 신규/구형을 판별할 수 없는 한계는 남는다. 명확한 구 기록만 legacy adapter로 읽고,
과거에 저장하지 않은 version/추가 필드/생략 여부를 복원된 원본이라고 주장하지 않는다.
owner 불명 결과는 자동 귀속하거나 공개하지 않는다.

현 방식은 payload와 기존 테이블을 함께 commit하는 호환 저장이다. 입력 snapshot·run 연결·
snapshot 선보존 후 게시·게시 실패 복구·삭제 후 늦은 worker 재저장 방지는 후속이다.
전용 저장소 전환은 reader 호환→AI 재호출 없는 이전→ID/내용/건수/검증 대조→writer 전환·복구
검증의 별도 작업이며 이 문서가 실제 자료 삭제 허가는 아니다.

## 검증과 남은 일

정상/자료 부족/가산 필드/생략/null/0과 잘못된 중첩 타입·UUID·ticker·날짜·version·JSONB 문자열을
합성 fixture로 검사한다. 저장 전 실패의 쓰기 0, root/자식/index 정합성, 신규 손상의 legacy 우회 차단,
실제 격리 PostgreSQL의 재조회·삭제·rollback과 자기 임시 자원 정리를 구분해 증명한다.
mock-only 통과는 실제 DB/로그인/인가 통과가 아니다.

현재 코드에는 CF-002의 인증·owner SQL이 추가됐다. 실제 AI·worker·공통 접수/멱등 경쟁·늦은 결과·
복구·숫자 인용 검증 보강은 후속이며, 수치 인용 결함을 이 저장 계약으로 해결했다고 주장하지 않는다.
기존 검사 기록은 [문서 목록의 검증 상태](../documentation.md#검증-상태와-이력)로 확인한다.

## 갱신 규칙

원본/확정 계약 변경을 먼저 검토하고 새 publication_version 파일과 manifest를 함께 갱신한다.
이전 파생본을 보존하고 현재 사용 버전은 문서 목록 한 곳에서 지정한다. 원본·파생 hash는 서로 다르다.
개인 경로·계정·대화·자격 사용 승인·원시 실행 영수증·비밀은 이 공유본에 포함하지 않는다.
