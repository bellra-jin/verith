## 관측·재현·한계

응답/요청 날짜는 남아 있지 않아 그 응답을 복원하거나 과거 단일 원인을 확정할 수는 없다.

별도 명시 승인된 현재 KIS-only 비교는 인증1회·시장3회·retry/OpenAI/계좌/주문0회로 완료했다.

## 확인한 제품 결함과 최소 수정

원본은 응답에 실제 들어온 최저 날짜 대신 요청 `chunk_start`로 다음 종료일을 옮긴다. 따라서
요청 앞부분이 생략된 짧은 W 응답을 받아도 그 prefix를 건너뛴다. 가짜 첫 창이03-31부터85개만
주고 작은 창에는03-24를 주는 경우, 원본 source를 기존 보호 runner에서 실행해 누락 회귀 실패를
확인했다. 이는 허용된 짧은 응답의 제품 재현이며 실제 과거 응답을 재현했다고 단정하지 않는다.

- **W만** 현재 요청 창 안의 유효 반환 최저 날짜의 전날로 cursor를 옮긴다. 응답보다 오래된
  미확보 prefix를 조회한다. D/M의 기존 종료/진전 계약과 모든 수치 설정은 유지한다.
- 비어 있지 않은 응답에 현재 창의 날짜가 없으면 고정 `KIS_RANGE_NO_PROGRESS` 불완전 오류다.
  섞인 과거/미래 행을 진전·종료 근거로 사용하지 않는다. 같은 날짜의 상충 값 거절은 보존한다.
- 같은 ISO 주에 다른 날짜의 봉이 반복되면 `KIS_WEEKLY_PERIOD_AMBIGUOUS`로 닫는다. 진행봉을
  완성봉으로 임의 채택하거나 서로 합치지 않는다. 원본 날짜를 월요일로 바꾸지 않는다. 휴장으로
  화요일/금요일에 표시된 한 주의 원본 라벨은 유지한다.
- 빈 응답 자연 종료는 유지한다. 기간당10페이지·기존 retry3·기한·소유 request gate는 불변이다.
  일반 source 최악 GET90과 실제 일회 gate30을 구분하며, 추가 페이지 때문에 gate가 먼저 닫히면
  partial을 정상 반환하거나 예산을 늘리지 않는다. 30회 내 전체 완료를 보장하지 않는다.

새 schema/상태/원장/수식/보간·주 단위 overlap을 만들지 않았다. 새 helper/runner도 없다.
기존 AI KIS pagination 검사8개를 보호 graph에서 실행하기 위해 내용 불변의 해당 검사 파일1개를
정확한 readonly source pin으로 추가했다. 그 외 guard·mode·worker·package 허용은 바꾸지 않는다.
