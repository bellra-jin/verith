## Google OIDC와 앱 세션

Google 한 제공자·Authlib의 비동기 HTTPX code 흐름과 PKCE S256을 사용한다.
scope는 **openid만**이며 profile/email·offline/refresh token·UserInfo fallback을 추가하지 않는다.
discovery는 https://accounts.google.com/.well-known/openid-configuration 이다. authorization/token/JWKS는
그 metadata와 코드의 허용 HTTPS 대상 기대값을 대조하며 임의 issuer·jku/x5u 키 URL을 따르지 않는다.
실제 client ID/secret·redirect/origin은 명시 구성하며 미설정은 fail-closed다.

state/nonce는 요청별 최소 32바이트 난수, verifier는 RFC7636 규약과 S256 challenge를 따른다.
5분 등 짧고 유한한 시도 상태에 nonce/verifier/고정 redirect와 시작 브라우저의 HttpOnly 상관관계
쿠키를 결합한다. callback은 누락·만료·불일치·중복 파라미터·이미 소비한 시도를 거부하고 **code 교환
전에 원자적으로 일회 소비**한다. 실패/거부는 새 로그인 요청부터 시작하며 code 교환 POST를
자동 재시도하지 않는다. 단일 프로세스 메모리 state는 재시작/다른 프로세스에서 실패하며 다중 인증
프로세스 지원이나 영속 복구를 보장하지 않는다.

ID token은 RS256 서명·신뢰된 JWKS·허용 kid/alg, aud/azp·exp/iat/선택 nbf·nonce/sub를 검증한다.
aud는 구성된 Web client와 일치해야 하고 배열 aud는 포함+azp 일치가 필요하다. exp는 지나면
거부하고 exp>iat, 미래 iat/nbf의 skew는 최대 60초다. sub는 비어 있지 않은 최대 255 ASCII 문자다.
서명 검증 전 issuer 입력은 `https://accounts.google.com`/`accounts.google.com` 두 정확한 값만
허용하며 모든 검증 뒤 내부 issuer를 전자로 연결한다. 다른 대소문자/슬래시/유사 도메인을 허용하거나
email/hd·클라이언트 UUID로 user를 선택/병합하지 않는다. Google token은 앱 API bearer가 아니다.

| 저장 대상 | 계약 |
|---|---|
| auth_users | 서버 발급 불변 UUID PK, created_at, nullable disabled_at. 이메일/비밀번호/외부 token을 저장하지 않음 |
| auth_identities | UUID PK, RESTRICT user FK, 대소문자 구분 issuer+subject UNIQUE·빈 값 금지. 최초 연결 경쟁의 패자는 새 user/identity savepoint를 rollback하고 확정 mapping을 재조회 |
| auth_sessions | UUID PK, RESTRICT user FK, 최소 32바이트 난수 token의 SHA-256 digest 32바이트 UNIQUE만 보존. 유한 created_at/expires_at과 expires_at>created_at, nullable revoked_at>=created_at CHECK |

TTL 기본 3600초는 기술상 기본값이며 양의 유한 값만 허용한다. sliding/remember-me는 없다.
매 요청 DB에서 세션 미폐기·미만료와 enabled user를 확인하며 상태를 캐시하지 않는다.
principal/UUID/digest 타입 검증은 공개 인증 방법이 아니다. raw 앱 token은 HttpOnly 쿠키로만
교환하며 query/body/임의 Authorization·X-User-ID·client_session_id를 대체 자격으로 쓰지 않는다.

상태 변경은 세션 결합 synchronizer CSRF와 정확한 Origin을 함께 검증한다. cookie는 HTTPS에서
Secure, HttpOnly·SameSite·Path 정책을 적용하며 로컬 HTTP 예외를 운영으로 확대하지 않는다.
로그아웃은 **세션 행을 처음부터 배타적으로 잠그고 폐기 commit 후** 쿠키 삭제/성공을 반환한다.
동시 로그아웃의 성공 1회/이미 폐기된 요청 401 정책과 삭제의 세션 공유 잠금을 구분한다.
폐기된 token은 재활성화하지 않는다. Google 전체 SSO 종료와 앱 로그아웃은 별개다.

## Flow 소유권·저장·삭제·migration

Flow root의 nullable owner_user_id FK가 정본이고 common index owner는 projection이다.
nullable은 legacy 보존용이다. 새 내부 저장은 검증된 principal을 요구하고 root/index owner를
같은 transaction에 기록한다. payload owner나 과거 common owner를 root에 복사하지 않는다.

모든 목록/count·상세/근거·batch·삭제는 root owner=principal.user_id와 해당 Flow root의 **index가
정확히 1행이며 그 owner도 동일**한 조건을 SQL로 적용한다. 중복/누락/고아/불일치/NULL index를
정상 결과로 취급하지 않는다. pagination 뒤 필터링하지 않고 count도 같은 조건을 쓴다.
안정 정렬은 created_at DESC/id DESC, offset/limit 응답은 유지한다. owner 확인 전에 payload를
복원하지 않는다. 미인증 401, 타인/없음/owner 불명 legacy 404다.

삭제는 유효 session 공유 잠금→root 소유권 조건/배타 잠금→index 정합성→해당 index·자식/root의
원자 삭제 순서다. index 선삭제나 타인 선수정은 금지하며 실패는 전부 rollback하고 stocks를 보존한다.
반복 삭제는 추가 효과가 없고 늦은 worker 재게시 차단은 후속이다. 새 writer의 root PK 경쟁과
root 잠금은 정합성을 직렬화한다. session 폐기 UPDATE는 공유 잠금과 직렬화되며 폐기 commit 뒤
시작한 수정은 거부한다. 이미 진행 중인 읽기 응답을 취소한다고 보장하지 않는다.

[스키마](../../backend/docs/schema.md)·[migration 절차](../../backend/docs/migrations.md)에 따라
기존 revision을 고치지 않고 확장 revision을 추가한다. auth 테이블 3개·nullable root owner FK·조회
인덱스를 추가하고 legacy JSON/ID/NULL owner/외부 common UUID를 보존한다. common 전역
FK/NOT NULL/Flow UNIQUE/정합성 trigger를 새로 강제하지 않으므로 **DB 전역 불변 보장**이 아니다.
인증 데이터/비NULL owner가 있으면 파괴적 downgrade를 거부한다. 실제 자료 변경/권한 부여는 별도다.

## 공개 경로와 우회 차단

본인 Flow GET 목록·상세/개별 DELETE와 공통 목록/archive만 인증 후 제공한다. 현재 archive의
지원 관점은 Flow이며 Technical 등 카드 shape 문서가 모든 기능의 공개 허용을 뜻하지 않는다.
공개 임의 save·모든 전체 삭제·다른 관점 생성/HTML/trace/관리·Next Supervisor의 Backend 미경유
직접 AI 경로는 upstream/쓰기 전에 차단한다. research/과거 화면을 mock 저장 성공으로 대체하지 않는다.
개인 응답은 private/no-store이며 원문 중복 쿠키를 임의 한 값으로 축약해 인증하지 않는다.
없는 Flow HTML/근거 endpoint를 이 작업에서 새로 만들지 않는다.

## 로컬 주소 계약

| 용도 | host 주소/매핑 |
|---|---|
| 브라우저 / Backend / AI | localhost:3200 / localhost:8200 / localhost:9200 |
| Google 외부 callback | http://localhost:3200/api/auth/callback (code 교환에도 동일) |
| PostgreSQL / Redis | 15432→5432 / 16379→6379 |
| Neo4j HTTP / Bolt | 17474→7474 / 17687→7687 |

Next 서버의 BACKEND_URL은 명시 설정하고 공개 NEXT_PUBLIC 값으로 fallback하지 않는다.
localhost/127.0.0.1·잘못된 port/Host/Origin을 인증에서 자동 동치로 처리하지 않는다.
AUTH_ORIGINS/CORS_ORIGINS·AUTH_REDIRECT_URI는 이 로컬 조합의 명시 허용값을 쓰며 운영 domain은
별도다. container 서비스명/내부 port는 그대로이고 모델 inference 8001/v1·검사용 ephemeral port는
이 host 계약으로 일괄 치환하지 않는다. [포트 안내](../local_ports.md)는 실행 승인이 아니다.
기존 ignored Compose의 실제 환경/자격/매핑을 clone에 존재한다고 가정하지 않는다.

## 격리 검증과 실행 권한 경계

일반 DB 테스트는 TEST_DATABASE_URL·승인된 별도 일회용 자원/제한 역할·앱 대상과의 분리를 확인한다.
누락/동일 서버/별칭/자격·소유 불명은 engine 생성/DDL/DML 전에 중단하고 앱 DB로 fallback하지 않는다.
asyncpg readonly preflight 뒤 engine, 그 실제 연결의 readonly 대조를 마친 **동일 연결**로 migration한다.

interactive runner의 별도 경로는 현재 runner가 local Docker에 직접 생성한 full ID/Created/label/nonce
영수증과 inspect가 일치한 자원만 다룬다. 원격 daemon·기존 container 채택·이름/manifest/marker 하나만의
증명·가짜 비교 URL/skip flag는 거부한다. read-only rootfs+필요 tmpfs, persistent mount 0·loopback
ephemeral 5432 binding과 비관리자 전체 제한 role flags, 매 runtime 새 연결의 첫 쓰기 전 readonly
식별/권한 재확인을 요구한다. bootstrap admin은 새 자원의 준비에만 쓰고 runtime에 넘기지 않는다.

임시 Backend/Next는 소스/설정의 명시 allowlist만 복사하며 .env/키/dump/log·symlink를 제외한다.
dotenv source를 앱 import 전에 끄고 parent env를 최소 allowlist로 제한한다. fresh exec·한정 DTO로
parent admin 메모리를 분리하며 Next에 Google/DB 비밀을 넘기지 않는다. 실제 외부 자격 사용은 실행별
구체 대상과 권한을 확인해야 하고 과거 로컬 실행 승인은 승계하지 않는다. 사용자 계정 조작은 자동화하지 않는다.
승인된 선택 reader를 사용하는 실행도 정확한 대상 키만 처리하고 multiline/중복/누락/공백/모호 구문을
원문 없는 오류로 거부해야 한다. 전체 dotenv source·보간·비밀 로그/argv/임시 파일 저장은 금지다.

자식은 생성 직후 추적하고 PID/PGID/시작 신원·실제 bind·nonce를 결합해 readiness를 확인한다.
유한 수명/parent EOF·오류/signal 시 자기 자식·증명된 자원·자기 사본만 정리한다. stopped 자기 자원도
소유 대조 후 처리하되 daemon/권한/timeout 오류를 제거 성공으로 보고하지 않는다. 실패는 영수증/잔여를
비밀 없이 보고한다. SIGKILL/호스트 종료의 자동 정리는 보장하지 않는다.

## 검증 수준과 미완료

오프라인 서명/claims·중복 callback·CSRF/Origin·우회 upstream 0·DB 사전 차단은 합성 검증이다.
실제 PG의 저장/조회/삭제·rollback/migration/경쟁은 DB 증거이며 실제 외부 Google 로그인을 대신하지 않는다.
외부 Google A/B는 사용자 수동 로그인과 실제 활성 identity/session·본인/타인 결과 경계를 각각 확인한다.
실제 시간 만료·폐기 뒤 옛 cookie의 Backend/BFF 재사용 거부, browser/cache·legacy/stocks 보존과
삭제 후 결과를 필요한 수준으로 따로 증명해야 한다. mock-only 통과나 PR 병합은 전체 수용이 아니다.
현재 보고된 통과/실패/미검증은 [검증 상태와 이력](../documentation.md#검증-상태와-이력)에 있다.
